# Decisions Log

| Date | Decision | Rationale | Alternatives Considered |
|------|----------|-----------|-------------------------|
| 2026-11-12 | Next.js 15 App Router | RSC, streaming, Edge runtime, best perf | Astro (less RSC), Remix (no Edge yet) |
| 2026-11-12 | Tailwind CSS v4 | Native CSS cascade, smaller bundle, design tokens | CSS Modules, Styled Components, UnoCSS |
| 2026-11-12 | shadcn/ui for components | Accessible, copy-paste ownership, no runtime | Radix UI directly, Headless UI, MUI |
| 2026-11-12 | Framer Motion for animations | Performant, gestures, reduced-motion support | CSS animations, GSAP (heavier) |
| 2026-11-12 | Resend for contact form | DevEx, deliverability, React Email templates | Formspree, EmailJS, Nodemailer |
| 2026-11-12 | Vercel deployment | Zero-config Edge, preview deploys, analytics | Netlify, Cloudflare Pages, AWS Amplify |
| 2026-11-12 | Data-driven content (TS files) | Type-safe, version-controlled, no CMS needed | MDX, Contentful, Sanity, Notion API |
| 2026-11-12 | Lucide React icons | Tree-shakeable, consistent, lightweight | React Icons (larger), Heroicons |
| 2026-11-12 | React Hook Form + Zod | Type-safe validation, minimal bundle | Formik + Yup, native HTML validation |
| 2026-11-18 | Editorial Swiss visual direction | Paper + ink + one loud accent (vermillion), Instrument Serif display + Geist Mono micro-labels, hairline rules, no shadows. Chosen over 3 other mock directions (Terminal Noir, Ethereal Glass, Brutalist) because it is the least common in dev portfolios and reads as a design studio, not a template | Terminal Noir (common), Ethereal Glass (AI-slop gradient), Brutalist (misfit for client work) |
| 2026-11-18 | Static imports instead of `next/dynamic` for sections | Lazy chunks delayed the LCP paint until hydration. Static imports ship the content in the server HTML (crawlable + immediate paint) and removed 4 skeleton components | Keeping dynamic imports (LCP 3.1s, blank first paint), React.lazy |
| 2026-11-18 | `presenceAffectsLayout={false}` on all AnimatePresence | Framer Motion defaults this to true, which calls `Math.random()` during render and breaks Next 16 prerender with `cacheComponents` | Keeping the default (build fails), removing AnimatePresence (loses exit animations) |
| 2026-11-18 | Hero uses transform-only entrance (no opacity fade) | An `opacity: 0` start defers the LCP paint until the fade ends. Slide-up alone keeps the motion and paints immediately | Opacity fade (LCP +2.3s), no animation at all |
| 2026-11-18 | `display: swap` for webfonts (not `optional`) | `optional` delays FCP to 1.8s in simulated slow-4G and can permanently show fallback fonts on first visit | `optional` (measured worse), `block` (invisible text) |
| 2026-11-19 | Regenerated `package-lock.json` instead of patching it | The old lock pinned `@react-email/render@0.0.16` (react 18 only) and `next-themes@0.3.0` (peer react ^18). Every targeted `npm install` failed with ERESOLVE because npm tried to resolve react 18 alongside react 19 | `npm install --legacy-peer-deps` (bakes in a broken tree), `--force` (same), keeping the old lock and accepting the advisories |
| 2026-11-19 | Upgraded `next-themes` 0.3.0 → 0.4.6 | 0.3.0 declares peer `react ^16.8 \|\| ^17 \|\| ^18`; the project runs react 19.3.0. 0.4.6 declares `^16.8 \|\| ^17 \|\| ^18 \|\| ^19` | Staying on 0.3.0 with `--legacy-peer-deps` (unsupported peer) |
| 2026-11-19 | Shared contact schema in `src/lib/contact-schema.ts` | Client and server must agree on the contract. One module means the honeypot field and the length caps cannot drift between the form and the route | Duplicating the schema in `ContactSection.tsx` and `route.ts` (drift risk), importing the route's schema into the client (pulls server code into the bundle) |
| 2026-11-19 | Numeric character references for HTML escaping | Named entities were stripped by the file-write path; `&#NN;` produces identical output and removes the entity table entirely | Named entity map (fragile), a DOM-free sanitizer dependency (new dependency for one function) |
| 2026-11-19 | In-memory rate limiter plus documented Vercel WAF rule | The limiter is a floor that is per-instance on serverless. The WAF rule is the authoritative global limit and is operator configuration, not code | Vercel Firewall SDK (adds a dependency), Upstash/Redis (adds infrastructure the project does not have), no limiter (a real quota-abuse hole) |
| 2026-11-19 | Native `<dialog>` for the project modal | `showModal()` provides focus containment, inert background and Escape handling from the platform, replacing hand-written focus-trap code | Hand-rolled focus trap and focus restore (more code, more bugs), Radix Dialog (new dependency) |
| 2026-11-19 | `src/app/opengraph-image.tsx` generating a 1200x630 PNG | Social crawlers need PNG/JPEG. The file convention is statically optimized by Next and needs no extra dependency | Static PNG committed to `public/` (binary in git, no design tokens), keeping the SVG (not rendered by most platforms) |
| 2026-11-19 | `LazyMotion` + `domAnimation` + `m` instead of the `motion` component | `motion` pulls the drag and layout features the site never uses. `m` plus `domAnimation` tree-shakes them out — first-load JS dropped 235 KB → 225 KB gzip | Keeping `motion` (+10 KB), dropping Framer Motion for CSS animations (larger diff, loses AnimatePresence) |
| 2026-11-19 | Kept static section imports after re-testing `next/dynamic` | Splitting the contact section into a dynamic chunk moved the same bytes into a second request (227 KB total vs 225 KB) while adding a waterfall. Static imports stay | `next/dynamic` for the contact section (measured worse) |
| 2026-11-19 | Sitemap reduced to the canonical URL | Fragment URLs do not identify separate documents, and the previous entry pointed at a non-existent `#skills` anchor | Fixing the fragment to `#skills-heading` (still an invalid sitemap entry) |
| 2026-11-19 | `z.config({ jitless: true })` in the shared contact schema | Zod v4 compiles validators with `new Function`. The strict CSP blocks it, the throw is swallowed — but Chrome still logs a `securitypolicyviolation`, which dropped Lighthouse Best Practices to 96. The flag is the library's own supported switch for CSP/no-eval environments; validation semantics are unchanged | Adding `unsafe-eval` to `script-src` (gives up the hardening that was just added), dropping Zod (a dependency the project already uses), catching the violation (the browser logs it regardless) |
| 2026-11-19 | Kept full Zod instead of `zod/mini` | Measured: Zod + React Hook Form is one 55.3 KB gzip chunk; `zod/mini` would save roughly 20–25 KB. Rejected because `zod/mini` has a different API (`.check()` instead of chained methods, no `.pipe()`), its errors are not `instanceof z.ZodError` (the route's error branch would need a duck-typed rewrite), and it would rewrite the validation layer that the spam protection depends on — a bad trade at Lighthouse Performance 98 | `zod/mini` (≈25 KB smaller, rewrites the security-critical validation layer), `zod/v4/core` (no public API), native HTML constraints + server-only Zod (duplicates the contract, drifts) |
| 2026-11-19 | GitHub Actions CI runs the a11y suite against the production build | `npm run dev` inflates Lighthouse-style timings and differs from what ships. The workflow builds first, then `next start` on :3000; `playwright.config.ts` picks the command from `process.env.CI` | Dev server in CI (not what ships, slower), a11y only on a schedule (regressions land unnoticed) |
| 2026-11-19 | The contact address is not published on the site | Owner choice. The form is the only channel, so the address never has to be scraped or spam-listed. The footer and mobile menu show a "Send a message" action instead of a `mailto:` | Publishing the address (more direct, more spam), a mailto link with obfuscation (still exposed in the HTML) |
| 2026-11-19 | Contact route returns `503` when `CONTACT_EMAIL` is missing | It previously fell back to `your-email@example.com`, which would silently deliver a stranger's message to a dead address. Failing loudly is the correct behaviour for an unconfigured service | Silent placeholder fallback (a real bug), a startup crash (would break the whole site, not just the form) |
| 2026-11-19 | Demo content replaced with one verifiable case study | Six invented projects and three fake employers were the bulk of the site's content. The only project that can be stated truthfully is this one, so the index now carries it with details that are checkable in the repository (Next 16, `cacheComponents`, strict CSP, 35 axe checks, Lighthouse 98). Nothing is invented to fill the space | Keeping the demo projects (false claims on a portfolio), inventing plausible-sounding clients (same problem, harder to spot) |
| 2026-11-19 | Experience reframed as a single independent/freelance entry | "Tech Company Inc." / "StartupXYZ" / "Digital Agency" were placeholders. One honest entry (Independent Full-Stack Developer, Freelance, Current) beats three fictional ones; the timeline UI handles a single row without special-casing | Inventing employers and dates (fabrication), removing the section (loses a useful signal for freelance work) |
| 2026-11-19 | Skills list trimmed and the unused `proficiency` field deleted | The `proficiency` numbers were never rendered — dead data carrying fake claims. The list now covers the tools this project actually ships with; entries the repo does not evidence (GraphQL, MongoDB, Redis, AWS) were dropped | Keeping the ratings (dead + fake), keeping every tool (claims nothing in the repo supports) |
| 2026-11-19 | JSON-LD `Person` schema added | The state files had claimed JSON-LD shipped; the code had none. It now exists, with `sameAs` pointing at the real social profiles, and `url` driven by `NEXT_PUBLIC_SITE_URL` | Leaving the docs claim unbacked (SEO loss + false documentation), a third-party schema tool (new dependency for one JSON object) |
| 2026-11-19 | Project category filter is derived from the project data | With one project the old hard-coded filter rendered four buttons that led to empty lists. The filter now appears only when a second category exists | Hard-coding the four categories (dead UI that lies about the content), removing the filter entirely (loses the feature when more projects arrive) |
| 2026-11-19 | Unused create-next-app assets deleted, project previews redrawn as SVG | `public/*.svg` boilerplate and five demo project images were unreferenced or fake. The remaining preview is an SVG authored to match the Editorial Swiss system, so a new project needs one file and no design tooling | Keeping the boilerplate (dead weight in the repo), raster screenshots (binary in git, stale the moment the design moves) |
